# Contratos inspeccionados y límites de integración

The public release starts with mock restaurant fixtures. The development OSM
snapshot mentioned below is not bundled; its importer remains available. Current
release evidence is in [TEST_REPORT.md](../TEST_REPORT.md).

La aplicación de reservas mantiene sus endpoints y reglas. AI Control Center añade las proyecciones administrativas y el inicio acotado de simulaciones descritos en [su guía](docs/control-center.md). `api.generated.ts` procede de `backend/contracts/openapi.json`.

| Necesidad                          | Contrato y adaptación                                                                                                                                                                                                                                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fotos y webs                       | `RestaurantOut` ya ofrece imagen principal, imágenes con licencia/atribución, `has_photo` y web. El catálogo inicial no tiene fotos/webs: se muestra placeholder y se omite Ver web.                                                                                                                                           |
| Catálogo real de restaurantes      | Implementado mediante importación manual y caché Overpass, persistida en SQLite. La UI usa reales cuando existen, con procedencia OSM/ODbL, selector de demostración y consultas por área visible. Primera importación: Madrid 9.217, Navarra 787. Sin garantías de cobertura o vigencia; sin fotos ni valoraciones inferidas. |
| Ubicación/selección/favoritos      | Consultas no modifican la reserva; favoritos y workspace tienen persistencia propia. La UI no reconstruye la cola a partir de resultados visibles.                                                                                                                                                                             |
| Añadir/reordenar/eliminar          | Endpoints existentes con posición desde cero, orden completo e `If-Match`. No se generan endpoints alternativos.                                                                                                                                                                                                               |
| Vaciar cola                        | No existe operación de borrado masivo. Se eliminan las entradas con DELETE consecutivos, usando la versión devuelta por cada escritura. Cada modificación es atómica; el vaciado completo puede ser parcial ante fallo y se reconcilia con GET. PUT order exige exactamente los IDs actuales: no acepta `[]` como borrado.     |
| Autosave                           | PATCH parcial serializado, conserva cambios que llegan durante la petición, `If-Match`, ningún reintento automático ante conflicto. Se conservan campos pendientes en memoria para revisar la versión y reintentar. No se copia información personal/alimentaria al almacenamiento del navegador.                              |
| Vistas                             | No es un valor de `table_type`; se persiste como `requirements[{key:"views",value:true,mandatory:...}]`.                                                                                                                                                                                                                       |
| Categorías                         | Cocina concreta con AND, agrupación Asiático y opciones vegetarianas/veganas/sin gluten declaradas por la fuente. La UI distingue menú declarado de seguridad ante alergias.                                                                                                                                                   |
| Resúmenes/contadores               | GET bookings paginado hasta recuperar todas las entradas. Pestañas y contadores derivados de estados persistidos. El modo de una ejecución se consulta en `/ai` cuando existe; una confirmación tiene su propio indicador `simulated`.                                                                                         |
| Tiempo real                        | WebSocket global con cursor y replay en SQLite, deduplicación y versiones. Al reconectar se invalidan consultas y se reconcilia REST sin descartar ediciones pendientes. El detalle tiene respaldo REST cada 5 s.                                                                                                              |
| Voz sandbox                        | El endpoint WebSocket y CLI de micrófono ya existen. El renderer no captura audio; Ajustes explica el comando, consentimiento y costes. No se representa como una llamada a un restaurante.                                                                                                                                    |
| Telefonía                          | El inicio real consume el contrato `call_authorization` existente. Desactivado si las capacidades no lo habilitan; solicita consentimiento, llamadas/duración/coste máximos y caducidad. Twilio, allowlist y tarifas se verifican en backend. No probado con llamadas reales.                                                  |
| Configuración de servicios y gasto | `/ai/capabilities` informa capacidades y modelos; no expone tarifas, allowlist ni escritura de configuración. Ajustes muestra lo disponible y remite al `.env` para los límites del backend.                                                                                                                                   |
| Transcripciones                    | No hay endpoint de transcripción completa; la UI muestra cronología, resultados, actividad y resumen existentes. No inventa conversaciones.                                                                                                                                                                                    |
| Distribución                       | Compilación y ejecución de Electron local. El empaquetado genera carpeta Windows; no incluye Python ni credenciales, instalador firmado, actualizaciones o instalación del backend.                                                                                                                                            |
